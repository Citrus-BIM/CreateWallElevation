# CreateWallElevation

Плагин RibbonCITRUS для построения развёрток по помещениям или выбранной стене. Создаёт разрезы либо фасады, применяет выбранный шаблон и размещает виды на листе при наличии места.

## Сборки

Поддерживаемый выпуск: Revit 2019–2026. Для 2019–2024 используется .NET Framework 4.8, для 2025–2026 — .NET 8. Требуются .NET SDK и targeting pack .NET Framework 4.8. Версии пакетов Revit API закреплены в Directory.Build.props.

Одна версия, оба варианта плагина:

```powershell
dotnet build CreateWallElevation.sln -c R2026
```

Все восемь версий в штатных bin каждого проекта, без PDB:

```powershell
powershell -NoProfile -File scripts/build-all.ps1
```

Результат:

```text
CreateWallElevation/bin/
  R2019/CreateWallElevation.dll
  ...
  R2026/CreateWallElevation.dll
CreateWallElevationSpectrum/bin/
  R2019/CreateWallElevation.dll
  ...
  R2026/CreateWallElevation.dll
artifacts/build/
  build-manifest.json
  build-R2019.log ... build-R2026.log
```

Две DLL с одинаковым именем относятся к разным вариантам ribbon-host; выбирать bin соответствующего проекта. Общий bin в корне решения не создаётся. DLL Revit API в поставку не включаются. Корневая DLL не перезаписывается скриптом. Восемь конфигураций .sln соответствуют поддерживаемому диапазону; сохранившиеся экспериментальные параметры R2027 не являются проверенным выпуском. Журналы и контрольные суммы находятся отдельно в artifacts/build.

## Расчёт и ограничения

- ViewDirection фасада направлен к наблюдателю. Направление объёма разреза задаётся отдельно, в сторону стены.
- Маркер фасада поворачивается шагами не более 30° с проверкой фактического направления после каждого шага. Это обходит известный сбой больших одиночных поворотов ElevationMarker (REVIT-134773); число попыток ограничено. Если направление не достигнуто, отчёт содержит остаточное отклонение.
- Отступ применяется один раз от поверхности. Для дуговой стены радиальное смещение вычисляется отдельно для каждой точки. Дуги разбиваются по настоящему параметрическому обходу.
- Внутренняя сторона определяется по исходным контурам помещения в плане, включая внутренние острова. Для проверки стороны дуги аппроксимируются с погрешностью хорды не более 0.1 мм. Это не разворачивание кривой поверхности в плоскость, а серия плоских видов.
- Соседние коллинеарные части объединяются до проверки минимальной длины. Через ниши и разрывы линии не соединяются.
- Поддерживаются горизонтальные прямые и дуговые границы. Для фасадов по помещению нужен активный план его уровня и фазы. Слишком большой отступ, недостаточная глубина, неоднозначная сторона или слишком крупный сегмент дуги дают сообщение вместо некорректного вида.
- Верх и низ комнаты берутся из её вертикальных ограничений с ProjectElevation. «Смещение снизу» по умолчанию 0: отрицательное значение (например, −100 мм) опускает нижнюю границу для показа пола, положительное поднимает её. Это действует для помещений и стен, разрезов и фасадов. Пустая или перевёрнутая рамка отклоняется с объяснением.
- Шаблон исходного проекта не изменяется. Если он блокирует геометрический параметр и задаёт несовместимое значение, объект пропускается с объяснением. Освободить соответствующий параметр в шаблоне или использовать подходящий шаблон. При отключённой галке также снимается шаблон по умолчанию типа вида.
- Каждый объект обрабатывается отдельной транзакцией внутри общей группы отмены. Создание каждого вида изолировано вложенной транзакцией: при ошибке этот вид и маркер отменяются, остальные развёртки помещения сохраняются. Отчёт перечисляет номера пропущенных развёрток и причины; нумерация соответствует исходным границам, поэтому возможны пропуски номеров. Ошибки подготовки помещения или окончательной фиксации его транзакции по-прежнему относятся ко всему объекту; фатальная ошибка регенерации останавливает пакет.
- Размещение учитывает габариты видового экрана и подписи, существующие виды и аннотации. Оставляются поля и нижняя полоса под штамп. Если места нет или лист без основной надписи, вид сохраняется без размещения на листе.

## Настройки

Обычный вариант читает и пишет `CreateWallElevationSettings.xml` рядом с фактически загруженной DLL. При запуске из `CreateWallElevation/bin/R2024` XML находится в этой же папке, а не в корне решения.

Spectrum использует отдельный пользовательский файл:

```text
%LOCALAPPDATA%/Citrus BIM/CreateWallElevation/CreateWallElevationSettings.xml
```

При отсутствии XML возле обычной DLL прежний общий файл AppData читается как источник миграции; последующее сохранение идёт только рядом с DLL. Существующий XML рядом с DLL имеет приоритет. Spectrum не обращается к расположению сборки, поэтому поддерживает загрузку из байтов. Варианты больше не перезаписывают настройки друг друга. Повреждённый XML не блокирует запуск. Сохранение атомарное; ошибка записи показывается пользователю и не отменяет выбранные параметры текущего запуска.

Настройки записываются после подтверждения параметров перед построением; отмена окна и ошибка валидации их не меняют. Выбранный шаблон запоминается также при выключенной галочке. «Без размещения на листе» сохраняется; отсутствующий в текущем проекте лист не заменяется первым доступным листом.

«Префикс имени вида» сохраняется между запусками. Пустое поле оставляет автоматическое именование. Пользовательский префикс заменяет автоматическую часть: для помещения 101 получится `АР_101_1_<ID>`, для стены — `АР_1_<ID>`. Номер развёртки и ID сохраняются для различения видов; недопустимые символы проверяются до выбора объектов.

Старый положительный нижний отступ при загрузке переводится в отрицательное смещение, чтобы сохранить прежнее положение рамки. В новом XML признак UsesSignedBottomOffset предотвращает повторную смену знака. Новые настройки начинаются с 0.

## Тестирование

```powershell
dotnet run --project tests/CreateWallElevation.Tests
```

Регрессионный исполняемый проект проверяет общий production-код геометрии, направления, дуги 270° в обоих обходах и с обеих сторон, контуры с отверстиями, слияние границ, знаковое смещение, префиксы имён, проверки чисел, раскладку и безопасное хранение и миграцию XML. Revit не требуется для этих проверок. Проверка реального создания видов, шаблонов и транзакций выполняется в Revit по docs/REVIT-ACCEPTANCE.md.

Проверка компоновки окна с настоящими WPF-ресурсами, без запуска Revit:

```powershell
powershell -NoProfile -STA -File scripts/preview-dialog.ps1
```

Скрипт создаёт PNG двух состояний каждого варианта и JSON с размерами контролов в `%TEMP%/CreateWallElevation-dialog-preview`. Проверяются границы формы, поля, радиогруппы, порядок Tab и отключённые состояния. Это проверка отображения XAML с демонстрационными данными; создание видов и события окна в Revit она не заменяет.

## Структура

- Shared/ — общий расчёт, Revit builder, раскладка, проверка ввода и хранение настроек.
- CreateWallElevation/ — обычный вариант, общие настройки и код окна, ресурс оформления.
- CreateWallElevationSpectrum/ — вариант Spectrum со своей точкой входа, телеметрией и оформлением; общий код подключён через Compile Link.
- tests/ — регрессионные проверки без Revit.
- scripts/build-all.ps1 — сборка в штатные bin проектов; диагностика отдельно в artifacts/build.
- scripts/preview-dialog.ps1 — воспроизводимый WPF-рендер и проверка компоновки обоих окон.
- AUDIT-2026-09-07.md — исторический аудит до исправлений.
