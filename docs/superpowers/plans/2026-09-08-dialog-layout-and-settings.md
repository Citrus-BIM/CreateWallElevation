# Компоновка окна и раздельное хранение настроек

Пользователь выбрал макет последовательной формы: «Построение», «Геометрия», «Именование и размещение». У выбранного варианта радиокнопки нет ни заливки фона, ни акцентной рамки: подсвечивается только круглый индикатор. Сохраняются оформление CITRUS, все параметры, нулевой нижний отступ по умолчанию и общий код двух вариантов.

Подтверждённые причины проблемы с настройками: оба варианта писали один XML в LocalAppData; XML возле DLL обычного варианта был лишь запасным источником. Для Spectrum дополнительно безусловно вычислялся путь Assembly.Location, который при загрузке из байтов пуст. Хост обычного варианта предпочитает DLL в bin, поэтому XML возле корневой DLL не является файлом возле фактически загруженной сборки. Сохранение в AppData работало; запись в ожидаемый пользователем файл возле DLL не выполнялась.

1. Обычный вариант читает и пишет CreateWallElevationSettings.xml возле своей загруженной DLL. Если файла там ещё нет, прежний общий XML AppData допускается только для чтения как источник миграции.
2. Spectrum читает и пишет только %LocalAppData%/Citrus BIM/CreateWallElevation/CreateWallElevationSettings.xml, не обращаясь к Assembly.Location. Общая модель и атомарная запись сохраняются; варианты больше не перезаписывают настройки друг друга.
3. Восстановление окна сохраняет выбранный шаблон даже при выключенном использовании. «Без размещения на листе» — явный вариант; пустой или исчезнувший сохранённый лист не подменяется первым листом проекта.
4. Реализовать выбранный макет в обоих XAML с общими именами контролов и событиями. Проверить реальный WPF Measure/Arrange и рендер, переключатели и состояния отключения, затем сборки 2019–2026.
5. После тестов и review — merge master и push, сборки в собственные bin каждого проекта. Пользовательская корневая DLL не меняется.

Проверено перед объединением:

- 94/94 регрессионные проверки, включая расположение XML, миграцию и независимость записей обоих вариантов.
- Отдельный запуск настоящего Spectrum SettingsLocationProvider в сборке, загруженной через Assembly.Load(bytes): пустой Location не мешает сохранению и чтению настроек. Проверка использовала временный профиль, пользовательский XML не менялся.
- Оба настоящих XAML отрисованы WPF в состояниях «помещение/фасад» и «стена/разрез». Все 32 имени контролов сохранены, переполнения нет, выбранный шаблон остаётся видимым при отключении, проверены шесть примеров имени и настройки клавиатурной навигации. Скрипт воспроизведения — scripts/preview-dialog.ps1; PNG и JSON итогового локального запуска — artifacts/ui.
- Матрица 2019–2026 обоих проектов прошла без предупреждений и ошибок. После последней корректировки примеров имени повторно собраны 2024 и 2026; после объединения запускается вся матрица с SHA итогового master в artifacts/build/build-manifest.json.
- Независимое ревью XAML, общего кода окна и хранения настроек: замечаний к объединению нет.

Рендер не запускает обработчики событий окна и не создаёт виды в Revit. Проверка повторного открытия в Revit, реальной клавиатуры и исходного проблемного помещения остаётся в docs/REVIT-ACCEPTANCE.md.
